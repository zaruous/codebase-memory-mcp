# codebase-memory-mcp 빌드 가이드

> 이 문서는 로컬 빌드 및 WSL 실행 경험을 바탕으로 작성된 실전 가이드입니다.

---

## 1. 빌드 환경

### 공식 CI 빌드 방법 (`.github/workflows/_build.yml` 기준)

| OS | 컴파일러 | 빌드 명령 |
|:---|:---|:---|
| Linux (Ubuntu) | gcc / g++ | `scripts/build.sh CC=gcc CXX=g++` |
| macOS | cc / c++ (Apple Clang) | `scripts/build.sh CC=cc CXX=c++` |
| **Windows** | **MSYS2 CLANG64** (clang) | `scripts/build.sh CC=clang CXX=clang++` |

출력 바이너리: `build/c/codebase-memory-mcp` (Linux/macOS), `build/c/codebase-memory-mcp.exe` (Windows)

---

## 2. Windows 빌드 옵션

### 옵션 A — MSYS2 CLANG64 (권장, Windows 네이티브 exe 생성)

1. [https://www.msys2.org](https://www.msys2.org) 에서 MSYS2 설치
2. MSYS2 CLANG64 터미널 실행 후 의존성 설치:
   ```bash
   pacman -S mingw-w64-clang-x86_64-clang mingw-w64-clang-x86_64-zlib make
   ```
3. 빌드:
   ```bash
   cd D:/git/python/codebase-memory-mcp
   scripts/build.sh CC=clang CXX=clang++
   ```

### 옵션 B — WSL2 Ubuntu (Linux 바이너리, WSL에서 실행)

WSL Ubuntu에 빌드 도구가 없는 경우 자동 설치됩니다.

```bash
# WSL에서 D: 드라이브 마운트 (최초 1회)
wsl -d Ubuntu -u root -- bash -c "mkdir -p /mnt/d && mount -t drvfs D: /mnt/d"
```

빌드 스크립트를 C: 드라이브에 저장 후 실행 (`D:` 드라이브는 WSL에서 직접 mount 필요):

```bash
wsl -d Ubuntu -u root -- bash -c "
  apt-get install -y build-essential zlib1g-dev   # 최초 1회
  cd /mnt/d/git/python/codebase-memory-mcp
  make -j4 -f Makefile.cbm cbm CC=gcc CXX=g++
"
```

출력: `build/c/codebase-memory-mcp` (ELF Linux 바이너리)

## 4. WSL에서 HTTP 서버로 실행

### systemd 서비스 등록 (영구 실행 권장)

WSL Ubuntu는 systemd를 지원합니다 (`/etc/wsl.conf`에 `systemd=true` 확인).

**`/etc/systemd/system/codebase-memory.service`** 생성:

```ini
[Unit]
Description=codebase-memory-mcp HTTP Server
After=network.target

[Service]
Type=simple
Environment=HOME=/mnt/c/Users/<사용자명>
ExecStart=/bin/bash -c 'sleep infinity | /mnt/d/git/python/codebase-memory-mcp/build/c/codebase-memory-mcp --mcp-http=true --mcp-http-port=9748 --mcp-http-local=false'
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> **`sleep infinity | ...` 파이프가 필수입니다.**  
> stdin이 EOF가 되면 MCP stdio 이벤트 루프(`cbm_mcp_server_run`)가 종료되어  
> HTTP 백그라운드 스레드도 함께 종료됩니다.

**서비스 시작:**

```bash
wsl -d Ubuntu -u root -- bash -c "
  systemctl daemon-reload
  systemctl enable codebase-memory.service   # WSL 재시작 시 자동 기동
  systemctl start  codebase-memory.service
  systemctl status codebase-memory.service
"
```

### WSL IP 확인 (Windows에서 접근 시)

```powershell
$wslIp = (wsl -d Ubuntu -- hostname -I).Trim().Split(" ")[0]
Write-Host "WSL IP: $wslIp"
```

`localhost:9748` 포워딩이 안 될 경우 **WSL IP를 직접 사용**합니다.  
`swagger_mcp_server`의 `codebase-memory.base-url`을 WSL IP로 변경:

```yaml
codebase-memory:
  enabled: true
  base-url: "http://172.24.206.29:9748"   # WSL IP (재시작 시 변경될 수 있음)
```

## 5. 포트 옵션

| 플래그 | 설명 | 기본값 |
|:---|:---|:---|
| `--mcp-http=true` | HTTP 트랜스포트 활성화 | false |
| `--mcp-http-port=N` | 포트 번호 | 9748 |
| `--mcp-http-local=true` | `127.0.0.1`만 바인딩 | **true** |
| `--mcp-http-local=false` | `0.0.0.0` 바인딩 (외부 접근 허용) | — |

> WSL에서 실행 시 **반드시 `--mcp-http-local=false`** 를 설정해야 Windows에서 접근 가능합니다.

## 6. 알려진 버그 및 수정 이력

### `filter_tools_list()` — yyjson linked-list iterator corruption

- **파일**: `src/mcp/mcp_http.c`
- **증상**: HTTP 모드에서 `tools/list` 응답이 첫 번째 비차단 툴(`search_graph`)을 13번 반복 반환
- **원인**: `yyjson_mut_arr_foreach` 순회 중 `yyjson_mut_arr_append(filtered, tool)` 호출이 `tool->next` 포인터를 덮어써 이터레이터가 같은 원소를 반복 방문
- **수정**: two-pass 방식으로 변경 — 1차 순회에서 포인터만 수집, 2차에서 append

```c
/* 수정 전 (버그) */
yyjson_mut_arr_foreach(mtools, idx, max, tool) {
    if (!tool_is_blocked(name))
        yyjson_mut_arr_append(filtered, tool);  // ← tool->next 오염!
}

/* 수정 후 */
yyjson_mut_val *allowed[32];
int allowed_n = 0;
yyjson_mut_arr_foreach(mtools, idx, max, tool) {   // 1차: 포인터만 수집
    if (!tool_is_blocked(name) && allowed_n < 32)
        allowed[allowed_n++] = tool;
}
for (int i = 0; i < allowed_n; i++)               // 2차: 안전하게 append
    yyjson_mut_arr_append(filtered, allowed[i]);
```

## 7. 데이터 디렉터리

| 환경 | 데이터 경로 |
|:---|:---|
| Windows 직접 실행 | `%USERPROFILE%\.cache\codebase-memory-mcp\` |
| Docker | `/data` (볼륨 마운트) |
| WSL 실행 | `$HOME/.cache/codebase-memory-mcp/` (`HOME=/mnt/c/Users/<사용자명>` 설정 필요) |

> WSL에서 실행 시 `HOME`을 Windows 유저 홈으로 설정해야 기존 인덱스 데이터를 재사용할 수 있습니다.
